# Движок игры: как устроен и как запускать

Ядро — чистый TypeScript без DOM и three.js (game-design §8.2). Контент приходит
из python-пайплайна (`content/nodes.json`, `content/squares.json`).

## Запуск

```bash
npm install --cache ./.npm-cache     # локальный кеш: ~/.npm недоступен на запись
npm run typecheck                    # tsc --noEmit, strict
npm test                             # vitest: 47 тестов
npm run content:build                # разбор книги → контент → подписи → приёмка
```

`npm run build` (Vite) появится вместе с UI-экранами: сейчас в проекте нет `index.html`.

## Структура

```
src/engine/types.ts       типы контента: Node, Choice, DiceCheck, Effect, Condition
src/engine/hero.ts        герой: готовый (+1 везде) и свой (сумма 6, ≤ +3, без уровня −2)
src/engine/dice.ts        2d6 + навык, зажим [2,12], выбор ветки по результату
src/engine/conditions.ts  доступность вариантов по отметкам (all/any)
src/engine/effects.ts     отметки, навыки, временные модификаторы с зарядами
src/engine/map.ts         карта 6×4, 8 соседей с диагоналями
src/engine/engine.ts      состояние, действия, журнал, снимки, откат
src/content/load.ts       парсинг JSON в типизированный контент + проверка ссылок
tests/                    юнит-тесты ядра, паритет с приёмкой, автопроходы
```

## Состояние и действия

```ts
const engine = createEngine(loadContent(), { startNode: 317 });
let { state } = engine.start(createReadyHero());

engine.choices(state);                                  // доступные кнопки
engine.reduce(state, { type: 'choose', index: 0 });     // выбрать вариант
engine.reduce(state, { type: 'roll', rng });            // бросок кубика
engine.reduce(state, { type: 'forward', to: '4В' });     // «Вперёд» по карте
engine.reduce(state, { type: 'enterSquare', id: '5В' }); // прочитать описание квадрата
engine.reduce(state, { type: 'rollback' });             // откат на шаг назад (§6.11)
```

`reduce` возвращает `{ state, effects, next }` — движок ничего не знает о UI,
поэтому его можно прогонять в консоли и в CI. Снимки состояния лежат в `state.history`,
что даёт откат и будущие сохранения (§8.6).

## Особенности контента, важные для кода

- **Эффекты двух уровней.** `node.effects` применяются при входе в узел
  («Поставь отметку 6»), `choice.effects` — только при выборе конкретной кнопки
  («Если ты возьмёшь ключ Розы, поставь отметку 23»). В узле 136 три кнопки ставят
  три разные отметки — применять их на входе нельзя.
- **Проверка без навыка** (узел 445) — бросок без модификатора, `check.skill === null`.
- **Временные модификаторы** («следующие два раза») хранят число применений
  и тратятся на каждой проверке; «до тех пор, пока не поешь» — бессрочный.
- **Условные кнопки** (`choice.checks`) — недоступные варианты движок не показывает
  вовсе: название не должно раскрывать скрытое требование (§10.2).
- **Ветки квадратов** проверяются по порядку; безусловное «Иначе» обязано быть последним,
  иначе перехватит игрока с нужной отметкой (см. `overrides.json`, квадрат 5В).
- **Редакторские связки** помечены `editorial: true` + `editorial_note` — их подписи
  задаются в `overrides.json`, а не в `labels_out/`.

## Замер автопроходов (300 партий, готовый герой)

- в среднем **133 хода** и **88 уникальных узлов** за партию;
- случайно достигнуто **12 из 15 финалов**: победа 20 раз, гибели 426/309/104/137/128/221/542/301/125/516/182;
- не встречены случайно: падение (526) и две гибели (243, 480) — их надо закрыть
  направленными «золотыми путями» (§7.5).
